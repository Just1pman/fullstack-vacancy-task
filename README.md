# Тестовое задание для Fullstack-разработчика

## Задача

Разработать небольшое приложение для просмотра, добавления и удаления пользователей.

Цель задания — показать навыки работы с JavaScript/TypeScript, асинхронными запросами, данными и REST API. Сложный интерфейс и production-ready инфраструктура не требуются.

## Функциональные требования

### Backend

Создать REST API для:

- получения списка пользователей;
- поиска пользователей по имени без учёта регистра;
- добавления нового пользователя;
- удаления пользователя.

Сервер должен:

- проверить наличие и корректность `name` и `email`;
- самостоятельно назначить уникальный `id`;
- вернуть созданного пользователя и подходящий HTTP-статус;
- вернуть понятную ошибку и подходящий HTTP-статус при некорректных данных.

Хранить данные нужно в памяти приложения

### Frontend

На странице необходимо:

- получить пользователей через API;
- вывести имя и email каждого пользователя;
- добавить поиск по имени;
- добавить форму создания пользователя;
- добавить возможность удаления пользователя;
- обновлять список после успешного добавления или удаления;
- показать пользователю состояние загрузки и сообщение об ошибке запроса.

Дизайн оценивается только с точки зрения базового удобства использования. Тратить время на сложную вёрстку не нужно.

## Технические требования

- Логика backend и frontend должна быть реализована на JavaScript или TypeScript без сторонних библиотек и фреймворков.
- Для backend необходимо использовать Node.js и его встроенные модули.
- Для frontend необходимо использовать HTML, CSS, JavaScript/TypeScript и встроенные API браузера.
- Допускаются только инструменты сборки и компиляции TypeScript. Использовать runtime-зависимости для реализации логики нельзя.
- Frontend должен получать и изменять данные только через созданное API.
- Сервер не должен доверять валидации на frontend: входящие данные необходимо проверять на backend.
- Код должен быть читаемым и разделённым по ответственности без избыточной архитектуры.

## Что приложить к решению

- исходный код проекта;
- `README.md` с командами установки и запуска;
- краткое описание выбранных технологий;
- комментарий о том, что вы бы улучшили при наличии дополнительного времени.

Решение должно запускаться локально по инструкции из `README.md`.

## Что не требуется

- авторизация и регистрация;
- база данных;
- сложный дизайн;
- Docker и CI/CD;
- деплой приложения;
- редактирование пользователей.

Дополнительные возможности не дают преимущества, если они усложняют проверку или ухудшают качество основной реализации.

## Критерии оценки

При проверке решения будут учитываться:

- знание JavaScript или TypeScript;
- работа с массивами, объектами и асинхронным кодом;
- понимание Promise и `async`/`await`;
- обработка ошибок и состояний загрузки;
- структура и читаемость кода;
- проектирование REST API;
- выбор HTTP-методов и статусов;
- серверная валидация входящих данных;
- разделение ответственности между frontend и backend;
- выполнение основных требований без неоправданного усложнения.
